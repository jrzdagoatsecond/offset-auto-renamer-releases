# Offset Auto Renamer

A rebrand + UI refresh of the batch file renamer tool, now with the Offset
Shop logo, a dark theme, and a license-key lock.

## What changed
- **Branding**: title, window text, and CLI banner renamed from "Nullex
  Auto Renamer" to "Offset Auto Renamer".
- **Logo/icon**: `icon.ico` and `illust.png` regenerated from the Offset
  Shop patch artwork you provided (cropped, squared, multi-resolution
  `.ico` for the taskbar/title bar/Alt+Tab).
- **UI**: switched to a dark, high-contrast theme (black background,
  silver/white accents) to match the embroidered-patch look, with a
  header banner that now shows the logo next to the app name. The
  interface has since been refreshed further with gradient primary
  buttons, soft accent-colored glows, and rounder cards for a more
  polished, "advanced" look.
- **Accent color picker**: click the round swatch button in the top-right
  of the header to open a color picker — choose from curated presets or
  pick any custom color. The chosen color drives every highlight (buttons,
  focus outlines, selection, checkboxes) *and* subtly retints all of the
  dark background panels to match, so one click reshades the whole app.
  Your choice is remembered automatically (via `QSettings`) and reapplied
  the next time you launch the app.
- **License lock**: on launch, the app checks for a saved valid key; if
  none is found it shows an activation screen that only accepts a key
  generated by the companion Key Generator tool.

## Files
- `app.py` — main GUI app (Offset Auto Renamer)
- `renamer.py` — CLI fallback version
- `keygen.py` — **Offset Key Generator**, a separate small GUI tool that
  mints valid license keys, verifies keys, and can deactivate/reactivate
  them. Keep this tool to yourself.
- `license_core.py` — shared key generation/validation/revocation-check
  logic (HMAC-SHA256 based). Imported by both `app.py` and `keygen.py`.
- `revocation_admin.py` — GitHub Gist API helpers used only by
  `keygen.py` to push/pull the hosted revoked-keys list. Not needed by
  `app.py`.
- `icon.ico`, `illust.png` — regenerated logo assets.
- `OffsetAutoRenamer.spec`, `OffsetKeyGenerator.spec` — PyInstaller specs
  for building Windows `.exe` files.

## How the key lock works
- `keygen.py` generates keys shaped like `OFST-XXXX-XXXX-XXXX-CCCC`,
  where the last group is an HMAC-SHA256 checksum of the previous groups,
  keyed by a shared secret (`SECRET` in `license_core.py`).
- `app.py` validates keys the same way — no internet/server needed for
  basic validation.
- **Key types**: in `keygen.py`, the "Type" dropdown next to Quantity lets
  you generate either **Lifetime** keys (never expire) or **1 Month**
  keys (expire 30 days after generation). The type and issue date are
  encoded in the first group of the key itself, so expiry is checked
  locally in `app.py` — no server needed, same as the checksum. Keys
  generated before this feature existed are treated as Lifetime keys, so
  nothing you've already handed out stops working.
- Once a valid key is entered, it's cached locally (in `%APPDATA%\OffsetAutoRenamer\license.dat`
  on Windows) so users don't have to re-enter it every launch.
- This is a lightweight, local gate — not real DRM. Anyone with the
  source (which includes `SECRET`) could generate their own valid keys.
  Before you distribute compiled builds widely:
  1. Change `SECRET` in `license_core.py` to your own private value.
  2. Only ship the compiled `.exe` files (built from source that has
     your private secret) — don't share `license_core.py` publicly.

## Deactivating a key (this is new!)
You can now turn off a key someone already has — it stops working the
**next time they launch the app, or immediately if the app is already
open**. Here's how it works and how to turn it on:

> **Why a Gist and not a file in this repo?** If your source repo is
> private (recommended, since it contains your build files), GitHub
> won't serve files from it to the app with no login — so the app could
> never actually check for revocations. A public **Gist** is a small,
> separate, standalone snippet that anyone can read with no auth, while
> your actual source code stays private. It only ever stores key
> strings, never your secret.

1. **Get a GitHub Personal Access Token**: go to
   https://github.com/settings/tokens → **Generate new token (classic)**
   → check the **gist** scope → generate → copy it.
2. **Open `keygen.py`**, click **⚙ Settings** in the "Deactivate a Key"
   section, paste your token in, and click **✨ Create New Gist**. This
   creates the hosted list for you and fills in the Gist ID.
3. **Copy the URL shown** ("license_core.py's REVOCATION_URL should be
   set to: ...") and paste it into `license_core.py`:
   ```python
   REVOCATION_URL = "https://gist.githubusercontent.com/raw/<gist_id>/revoked_keys.json"
   ```
   Leave it blank (the default) to disable revocation checking entirely.
4. Click **Save** in the Settings dialog.
5. **Rebuild `OffsetAutoRenamer.exe`** (Actions tab → re-run the
   workflow, or push a commit with the updated `license_core.py`) so
   the new `REVOCATION_URL` is baked in.

From then on:
- In **Offset Key Generator**, type or right-click any key and choose
  **Deactivate** — this pushes an update to your gist. You can also
  **Reactivate** a key the same way.
- In **Offset Auto Renamer**, every launch checks the gist. If the
  saved key is on the list, the person is kicked back to the activation
  screen with "This key has been deactivated."
- **The check also runs live while the app is already open** — every
  60 seconds (`LIVE_REVOCATION_CHECK_INTERVAL` in `license_core.py`) it
  quietly re-checks the current key in the background. If it's been
  deactivated, the tool is immediately hidden and the activation screen
  pops up on top of it — no restart needed. Entering a new valid key
  unlocks and re-shows the tool right where it was; closing that dialog
  instead exits the app.
- If the person is offline when they launch it, the app uses its last
  successfully-fetched copy of the list (cached locally, refreshed
  every 30 minutes for the startup check) rather than blocking them
  entirely — so a single dropped connection won't lock out someone
  who's already active, but the deactivation will still catch on the
  next time they're online.
- GitHub's raw CDN (`gist.githubusercontent.com`) can take a few
  minutes to reflect a change after you deactivate/reactivate a key —
  if a test doesn't seem to take effect instantly, that's normal; give
  it a couple of minutes.

**Keep `keygen.py` and your access token private** — anyone who has
them can create/edit gists on your account. The `keygen_config.json`
file it saves your token into
(`%APPDATA%\OffsetAutoRenamer\keygen_config.json`) is local-only and
never gets bundled into the distributed `.exe`s — don't commit it to
your repo.

## Building the Windows .exe files

### Option A — GitHub Actions (no Windows machine needed)
This repo includes `.github/workflows/build.yml`, which builds both
executables on a free `windows-latest` GitHub Actions runner.

1. Create a new (can be private) GitHub repository and push this folder
   to it — the `.github/workflows/build.yml` file must be at that path
   relative to the repo root.
   ```bash
   git init
   git add .
   git commit -m "Offset Auto Renamer"
   git branch -M main
   git remote add origin https://github.com/<you>/<repo>.git
   git push -u origin main
   ```
2. Pushing to `main` automatically triggers a build. You can also trigger
   one manually: go to the repo's **Actions** tab → **Build Windows
   executables** → **Run workflow**.
3. When the run finishes (green check), open it and scroll to
   **Artifacts** at the bottom — you'll see `OffsetAutoRenamer` and
   `OffsetKeyGenerator` zip files. Download and unzip each to get the
   `.exe`.

No local Python or Windows install required for this route — GitHub's
runner does the packaging.

### Option B — Build locally on a Windows machine
```bash
python -m venv venv
venv\Scripts\activate
pip install pyqt5 pyinstaller
pyinstaller OffsetAutoRenamer.spec
pyinstaller OffsetKeyGenerator.spec
```

The finished executables will be in `dist/OffsetAutoRenamer.exe` and
`dist/OffsetKeyGenerator.exe`.

## Running from source (any OS with Python + PyQt5)
```bash
pip install pyqt5
python app.py       # main tool (asks for a key on first run)
python keygen.py     # generate/verify keys
```
